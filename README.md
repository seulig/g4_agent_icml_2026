# g4_agent_icml_2026

Data and code for the ICML 2026 AI4Science workshop paper:

**"Position: Correct Answer, Wrong Mechanism — When AI Scientists Defend General Claims Their Own Data Contradicts"**  
Steven Young Eulig, Harvard LPPC  
ICML 2026 AI4Science Workshop (Spotlight)

---

## Contents

### `harness/`
- `run_episode.sh` — launches a Claude Opus 4.6 episode inside `script` for transcript capture; locks sibling directories to prevent cross-episode contamination
- `run_gemini_episode.py` — runs a Gemini 2.5 Flash or Pro episode via the Vertex AI API

### `configs/`
Four prompt variants spanning an information gradient:
- `prompt_A.txt` — open-ended (no observable hint)
- `prompt_B.txt` — 5-step scaffold (process guidance, no observable hint)
- `prompt_C.txt` — positive control (f_early formula + physics motivation provided)
- `prompt_D.txt` — biased prior (σ and f_early both seeded; one claim is false)

### `scripts/`
- `check_cawm_predictions.py` — the §5 verification harness. It formalizes each of the 7
  CAWM episodes' stated mechanism as a signed prediction and tests it against that episode's
  own ROOT files, using two one-step ground-truth checks (a regime-shift test for the
  over-generalized σ claims and a companion recomputation for the confounded relative-window
  cases). Running it on this repository reproduces the paper's result: **7/7 CAWM cases caught
  (4 by the regime-shift test, 3 by the companion recomputation)**, plus an outcome check on
  the cross-model Prompt A episode, whose result fails at its own anchor and which the paper
  codes as a detectable failure rather than CAWM (Figure 1).

**Dependencies:** `pip install uproot numpy` — no Geant4 or ROOT installation required.
Run with: `python scripts/check_cawm_predictions.py`

### `episodes/primary/` — 20 episodes, Claude Opus 4.6
Each episode directory contains:
- `PROMPT.txt` — the exact prompt used
- `*_hits.root` — raw Geant4 simulation output (PhotonHits TTree: hitTime, eventID, photonOrigin)
- `*_args.json` — simulation run parameters (particle, energy, impact parameter, n_events)
- `*.png` — analysis plots generated by the agent during the episode

The quantitative basis for every CAWM coding is fully reproducible from the released ROOT
files and the `scripts/` checker, so a second reader can verify each coding independently.

Two authentic data gaps from the original runs: `primary/ep_004/mu_d10_hits.root` is the
empty file the simulation produced during that episode (the agent's analysis treated the run
as zero hits), and `primary/ep_005` has no electron run at d = 25 m (the agent never executed
it). Neither affects a CAWM coding or the verification script.

Prompt assignment: ep_001–005 = Prompt A, ep_006–010 = Prompt B, ep_011–015 = Prompt C, ep_016–020 = Prompt D

### `episodes/gemini_flash/` — 4 episodes, Gemini 2.5 Flash
One episode per prompt (A, B, C, D). Each contains:
- `*_hits.root` — simulation output
- `*_args.json` — run parameters

### `episodes/gemini_pro/` — 4 episodes, Gemini 2.5 Pro
Same structure as gemini_flash (ROOT files + args.json only).

## Simulation

The simulator is **OMSim** (Geant4-based optical module simulation). The binary is not included here; see the OMSim repository for build instructions.

Run command:
```bash
./OMSim_WavePID_study -n 50 --detector_type 3 --environment 2 \
  -d <impact_m> -e <energy_GeV> -p <particle> -o <output_prefix>
```

Key flags: `-d` impact parameter (m), `-e` energy (GeV), `-p` particle (`mu-`, `e-`), `-n` events.  
All episodes use E = 40 GeV and 50 events per run, with d ∈ {10, 20, 25} m prescribed for Prompts B/C/D and agent-chosen within 10–25 m for Prompt A (each episode's exact grid is recorded in its `*_args.json` files).

## CAWM Coding Audit

All CAWM episode codings can be independently audited by applying the decision rule from §2 of the paper to the released simulation data and prompts. An episode is CAWM when the agent's stated mechanism either contradicts its own numerical output or generalizes beyond tested regimes without qualification.

The regime-shift verification script (`scripts/check_cawm_predictions.py`) formalizes each CAWM case as a signed directional prediction and checks it against the ROOT files in this repository.
